# Module: backup and restore
Status: rules (P3-2a), service and restore (P3-2b) and the screens with the automatic triggers (P3-2c) built 2026-11-21; nobody has seen the screens, and nothing was tried with a real USB drive or on a real Windows machine

Purpose: a daily copy of the encrypted database to two places, and a tested way back to a clean machine.

- **Asked by owner:** no lost sales data (biggest fear, ADR-0015).
- **Rules:** SSOT 20; ADR-0015; ADR-0003 points 7 to 11 (the backup is the encrypted file, so a restore needs the key or the recovery key).
- **Owner decisions (2026-11-21):** a backup is made when the last open shift of the day is closed, and again when the app starts if none was made today (India day); the owner picks the USB drive and a second folder with a folder picker in Manager Mode (needs one more package, `file_selector`); the last 60 backups are kept in each place, older ones deleted automatically (never the newest). Earlier: both a USB drive and a folder (ADR-0015, D6).
- **Rules built (P3-2a):** `BackupName` (`apparel-pos-YYYYMMDD-HHMMSS.backup`, India time, sorts in time order; anything else is not a backup name), `backupsToDelete` (oldest beyond the limit, ignores files that are not ours, never deletes the newest), `isBackupDue` (none made on today's India day; a backup dated after now does not block), `backupAfterClose` (only when no shift is left open).
- **Service built (P3-2b, `apps/pos_windows/lib/data/backup/backup_service.dart`, desktop only):** `BackupService`: `setPlace` (slot 1 or 2), `status` (places, last attempt, last saved, last complete, failures per place; manager and owner only), `isDue`, `backupNow` (manager and owner), `backupIfDue` (start-up) and `backupAfterShiftClose` (both automatic, never throw: a failure is recorded for the manager and billing goes on). A backup is a consistent snapshot of the running encrypted database made with `VACUUM INTO` (SQLCipher keeps the key), checked by opening it with the key (`PRAGMA integrity_check`), copied to each place under a `.partial` name, checked again, then given its final name; old backups beyond 60 are deleted per place (never files that are not ours). A place that is not there (USB not plugged in) is not recreated: the other place still gets its copy, the day counts as partly done (`backup_last_complete_at` is set only when every place succeeded) and is tried again at the next close or start-up. Each run is audited and queued with counts only: no paths and no key. `restoreBackup` (the database must be closed): checks the backup with the key (the recovery key on a new machine, else the credential store) before changing anything, keeps the current database aside as `<db>.before-restore-<time>` (with its journal files) until `discardBeforeRestoreCopies` (the owner confirmed), puts it back if the restore fails, refuses a backup from a newer app version, and refuses a computer that already holds a different key (`RestoreKeyMismatch`: replacing it would make the aside copy unreadable; limitation, ask the assistant). **E-BACKUP-1** test: backup to two places, restore into a clean directory with an empty key store and only the recovery key text, and compare every row of every table. The checks that follow are the old plan:
- **Plan:** P3-2b backup service (consistent snapshot of the encrypted file, copy to both places, check each copy opens, prune, record last backup and any failure, restore into a clean place) with the E-BACKUP-1 restore test on a clean directory and an empty key store using the recovery key; P3-2c screens (folder pickers, Back up now, last backup and failures shown to the manager only, restore, automatic backup at shift close and at start-up).
- **Screens built (P3-2c):** Manager Mode gets a Backups button and a banner on top (`backup_banner.dart`): it warns when backups are not set up, when a place failed (naming it) and when no complete backup was made today, and is calm otherwise; cashiers never see it. The Backups screen (`backup_screen.dart`) shows the two places (USB drive, second folder) each with a system folder dialog (`file_selector`) to choose or clear, the last complete backup, any failure with its reason, Back up now (says how many places got a copy and why a place failed), a Restore button, and a note with a delete button for the kept-aside data after a restore (asks for confirmation). The Restore screen (`restore_screen.dart`): choose the backup file with the system dialog, type the recovery key if this computer does not hold the key, type RESTORE exactly; in Manager Mode the owner's or a manager's password is asked again (the same pop-up as discounts); the backup is checked before the database is closed, so a wrong key or a bad file leaves the app running; on success it says Restore finished and closes the app so the data is opened fresh (owner, 2026-11-21). On the first launch of a new computer the set-up screen has a link to the same screen, with no password (no user exists yet; refused if any user exists) and the key made for the empty new database is replaced by the backup's (`replaceKey`; never used over shop data). Automatic triggers: start-up (`backupIfDue`, in `main.dart`) and after the last open shift closes, including the forced close of an earlier day's shift (`AppServices.backupAfterShiftClose`), in the background; failures are recorded for the manager only. The screens talk to a web-safe `BackupController` (`backup_models.dart`); the desktop one is `NativeBackupController`; the browser preview has none and says so.
- **Not built:** who may run a restore at first launch before any user exists (the screen will allow it only when there are no users); reading backups from a different app version than the database (refused); a backup of the key itself (the recovery key on paper is the way). Unverified: speed and behaviour with a real USB drive on Windows (a drive letter that disappears, a slow drive).
- **Not in scope yet:** upload to the cloud (comes with sync, release 2).
- **Evals first:** E-BACKUP-1.
- **Open decisions:** none. Assistant's choices, unconfirmed: place 1 is called USB drive and place 2 Second folder (the app does not check that place 1 really is a USB drive); the banner treats a day without a complete backup as a warning from the start of the India day; a restore refuses a computer that already holds a different key except on the first launch.
